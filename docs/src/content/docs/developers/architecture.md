---
title: Architecture
description: How the RenderCV app is organized across packages, workers, stores, and routes.
---

The repository is a pnpm workspace with a React web app, an API app, shared contracts, shared core logic, and a Starlight docs package.

## Workspace Layout

- `apps/web`: Vite React app.
- `apps/api`: API server.
- `packages/contracts`: shared TypeScript contract types.
- `packages/core`: shared stores, data, templates, preview helpers, and business logic.
- `themes`: RenderCV theme assets and Python theme code.
- `static`: browser-served runtime assets, fonts, wheels, and WASM bundles.
- `docs`: Astro Starlight documentation site.
- `themes/resume`: Python RenderCV theme and theme test tooling.

## Web App

The web app uses React 19, Vite, Tailwind CSS v4, React Router, Monaco, and browser workers.

The web app uses React Router with these major routes:

- `/`: main workspace.
- `/preview`: preview-focused route.
- `/share`: encoded share route.
- `/review-import`: review package import route.
- `/review/:sessionId`: review session route.
- `/migrate`: migration route.
- Legal routes for privacy and terms.
- `/portal`, `/prototype-renderers`, and `/sentry-test`.

Vite uses `base: '/rendercv-app/'`, serves `../../static` as its public directory, aliases workspace packages to source files, and proxies `/api` to `VITE_API_TARGET` or `http://localhost:8787` in development.

## State

Core app state lives in stores from `@rendercv/core`.

Important stores include:

- `fileStore` for CV files and undoable edits.
- `preferencesStore` for UI and editor preferences.
- `reviewStore` for review sessions and proposals.

The shared contracts package defines `CvFile`, `CvFileSections`, API DTOs, preferences, billing, public CV, feedback, GitHub, AI, and review types.

## Rendering

Rendering is split across browser workers:

- `pyodide.worker.ts` loads Python/RenderCV dependencies and converts YAML to Typst-compatible output.
- `typst.worker.ts` compiles Typst output for preview and export.

The React hook `useViewerRenderer` coordinates worker initialization, caching, validation, and preview requests.

The preview popup uses a BroadcastChannel protocol from `packages/core/src/preview/channel.ts` with messages such as `ready`, `closed`, `ping`, and `filestate`.

## Static Assets

Runtime assets live under `static/cdn` and include:

- Pyodide wheels.
- Typst compiler/renderer WASM.
- Fonts.
- Bundled theme assets.

The web build copies and references those assets for offline-friendly rendering.

Theme zips and `bundled-themes.generated.ts` are generated by `apps/web/scripts/sync-bundled-themes.mjs` before web dev/build.

## API Server

The API app is a Hono server. `apps/api/src/index.ts` starts the Node server on `PORT` or `8787`, and `apps/api/src/server/app.ts` mounts all `/api/*` routes.

The current route implementation persists to `apps/api/data/state.json`. Drizzle database client/schema files exist for future database-backed persistence, but current routes use JSON state.

API errors are normalized into structured JSON for validation errors, invalid JSON, not found routes, and internal errors.

## Sharing and Review

Share and review flows use compressed packages and URL encodings from `apps/web/src/features/share` and `apps/web/src/features/review`.

Review sessions compare origin snapshots with proposed changes and can create merge drafts.

## Testing

Tests are split by package:

- Core store and helper tests in `packages/core`.
- API route tests in `apps/api`.
- Web feature tests in `apps/web`.
- Contracts package currently allows no tests.

Run all tests from the repository root with:

```sh
pnpm test
```

CI uses Node 22, pnpm, frozen install, recursive typecheck, recursive tests, and recursive build.
